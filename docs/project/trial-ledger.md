# 시행 원장 (trial ledger)

- 개설: 2026-08-18
- 근거: [`../research/trial-accounting.md`](../research/trial-accounting.md) §8.8·§10-1
- ⚠️ **이 파일은 git 추적 대상이고 원격은 public이다.** 계좌번호·잔액·보유 종목을 쓰지 말 것.
  들어가는 것은 백테스트 지표뿐이다.

## 왜 두 층인가

임상시험 등록과 다중검정 보정은 **N이 커질 때의 유인이 반대다.** 임상에서는 누락이 위법이라
많이 등록하는 게 안전한데, DSR은 N이 크면 임계 `SR₀`가 올라가 **정직하게 세면 자기 결과가
기각되고**, PBO는 쓰레기 열을 넣으면 **결과가 왜곡된다.** 그래서 "일단 다 적어 두자"는 임상식
해법이 그대로 안 통한다.

- **층 ① 실행 로그** — 돌린 것은 **무조건 전부.** 판정 자격을 묻지 않는다.
- **층 ② 시행 카운트** — 보정 통계량(DSR·PBO)에 먹일 N. **규칙에 따라 ①에서 승격**한다.

문헌도 같은 구조를 갖는다 — OSF는 confirmatory 변수만 열거를 요구하고 탐색 변수는
*"you are not required to list them"* 이며, COS Registered Reports는 등록 분석과 사후 분석의
**구분 표시**만 요구한다.

## 층 ② 시행 카운트 (N)

### 세는 규칙

**1회 = `(핸들러 × 모델 × 라벨정의 × 세그먼트 × 하이퍼파라미터 설정)` 조합 하나에 판정을
내리는 것.** [`microcap-insider-prereg.md`](microcap-insider-prereg.md) §4.1의 형태를 신호탐색
쪽으로 옮긴 것이고, 원리는 같다 — **고를 수 있으면 센다.**

| | 세나 | 이유 |
|---|---|---|
| 하이퍼파라미터 후보 하나 | **센다** | 6개 중 하나를 고를 수 있다 |
| 같은 설정의 시드 하나 | **센다**(단 아래 N̂ 주석) | 시드 간 최선을 고를 수 있다 |
| 라벨 호라이즌 변경 | **센다** | 설계축이다 |
| 배선 스모크·`generate_signal` | 세지 않는다 | 판정을 내리지 않는다 |
| 게이트·계측 도입 | 세지 않는다 | **유리한 셀을 고를 수 없다.** 기각만 한다 |
| 결함 수정(embargo 등) | **센다** | 판정을 바꿀 수 있다 |

⚠️⚠️ **이 규칙은 문헌이 준 것이 아니다.** Harvey & Liu는 *"we need to use judgment on an
important input—the number of tests"*, OSF 템플릿은 *"Explain how … will be accounted for"* 라고만
한다 — **금융·통계 쪽과 사전등록 플랫폼 쪽이 독립적으로 같은 칸을 비워 뒀다**
([`trial-accounting.md`](../research/trial-accounting.md) §7). 위 표는 이 저장소의 결정이며,
"문헌이 그러라고 했다"고 인용할 수 없다.

문헌이 준 구체적 규칙은 둘뿐이다:

1. **유도탐색의 중간 스텝은 세지 않고 수렴 결과 하나가 M의 열이다** (PBO §5.2).
   ⚠️ 이건 **CSCV 행렬 M의 열 정의이고 DSR의 N이 아니다.** 섞으면 안 된다.
2. **실패가 예정된 시행으로 N을 부풀리지 않는다** (PBO §5.2). DSR과 방향이 반대다 —
   DSR은 N이 크면 보수적이지만 PBO는 왜곡된다.

### 현재 N

| 집계 방식 | 값 | 용도 |
|---|---:|---|
| 위 규칙에 따른 설계축 시행 | **≥ 24** | 이 원장이 쓰는 값 (L-006으로 +1) |
| 동일 183주 손익계열 열 수 | 9 | CSCV가 실제로 쓸 수 있는 것 |
| 그 9열의 서로 다른 설정 수 | 3 | 시드·재실행 제거 후 |
| MLflow 런 수 | 23 | UI에 보이는 것 |
| DSR 부록 A.3의 실효 `N̂` (실측 상관에서) | **4.86** | DSR에 먹인 값(가장 관대) |

★ **9와 26 사이에 세 배 차이가 있고 어느 것도 "맞는 N"이 아니다.** 그래서 위 다섯 줄을 다
남긴다 — 어느 값을 썼는지가 감사 가능해야 한다.

**MinBTL 예산**: 표본 183주 = 3.52년 → "IS Sharpe 1인데 OOS 기대 0"을 피할 수 있는 최대 독립
시행은 **N = 18**. **이미 초과했다.** 게이트가 아니라 게이지로 읽는다 — 예산 소진은
"새 시행보다 표본 확장이 먼저"라는 신호다.

## 기록 규약

1. **학습을 돌리면 층 ①에 무조건 한 줄.** 결과가 나쁘든 중간에 죽든 적는다. 안 적으면
   그 시행은 영구히 보정 밖이고, 사후 집계는 구조적으로 과소계산된다.
2. **`손익` 열을 먼저 본다.** `report_normal_*.pkl`이 남지 않는 실행은 DSR·PBO 입력이 못 된다.
   스윕을 짤 때 이걸 남기는지부터 확인할 것.
3. **커밋 해시로 가리킨다.** 행 번호는 낡는다. `mlflow.source.git.commit`이 자동으로 남으므로
   커밋 열은 공짜다.
4. **`confirmatory` / `exploratory`를 반드시 적는다.** 탐색을 금지하는 게 아니라 **구분**한다 —
   COS RR·OSF가 공통으로 요구하는 최소 라벨이고, 이 열 하나가 그 규율 전체를 구현한다.
5. **층 ②로 승격할 때 규칙 표를 다시 읽는다.** 애매하면 세는 쪽으로.
6. **스윕은 `_common.trial_run()`으로 돈다.** 직접 `model.fit()`을 반복하면 런이 하나로 접힌다.
   같은 스윕의 시행은 `sweep_id` param으로 묶이고, 후보 선택은 `kind="selection"` 런에 남는다
   (선택은 시행이 아니므로 층②에서 세지 않는다 — 세면 이중계상이다).
   ⚠️ **부모-자식 런은 쓸 수 없다** — `MLflowRecorder.start_run`이 `mlflow.start_run`에
   `nested`를 넘기지 않는다. `sweep_id` 태그가 그 역할을 대신한다.
